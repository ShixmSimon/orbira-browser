## 4. 日常维护规则（写给未来的自己/AI）

**新增一个引擎侧本地修改的标准动作：**
1. 改 `overlay/` 里的文件，或新建 `patches/ohos-<name>.patch`（LF！补丁一律 LF，见 `.gitattributes`）；
2. 注册三处清单：`scripts/apply-adapter.sh`、`scripts/ci-incremental-build.sh`、`wb-wsl-stage3d-patches.sh` 的 PATCHES 列表；
3. `local-patches/MANIFEST.txt` 加行（`git hash-object` 算指纹）+ snapshots 副本 + `verify-originals.sh` 加 marker；
4. `sync-154.cmd` 的 PROTECTED 加上新文件；
5. 本地 commit（不 push）；
6. 若改了管线脚本 → `bash local-pipeline/refresh.sh` → 再 commit。

**血泪反模式（每条都踩过）：**
- ❌ 改 WSL src 不改 overlay → 下次构建被 `rsync overlay/ → src/` 冲掉（桌面 UA 补丁三连败的根因）。
- ❌ 改 `patches/ohos-browser-controls.patch` → 它是副本，不在任何 apply 清单，改了不生效。
- ❌ 让引擎侧修复只活在仓库外 patcher 里 → 本次 Origin 补丁的教训；现在已固化为 git patch。
- ❌ `git clean -fd` → 删掉整个移植。
- ❌ 信「改了就编进去了」→ 唯一硬判据是 .so 的 sha256 变化 + verify-originals 的 7 个标记。

## §7 GitHub 上的代码是否“完整”、克隆后能否重建当前 HAP（2026-10-23 实测，11:45 修订）

**结论先行：本仓（ShixmSimon/orbira-browser 即 chromium-hmos）是【修改层】，不含 Chromium 源码；
但它对“真实内容改动”的覆盖率是 100%。在别处重建 HAP = 谷歌 154 底座 + 本仓 + SDK + DevEco + 签名，不需要上游 fork。**

### 7.1 实测方法（权威口径）
对 WSL 中正在产 HAP 的 src 树（HEAD=`b510e9d7cd`=154.0.8037.97）跑 `git diff --numstat HEAD`（3798 条），
按“是否有真实内容改动”分类，再与本仓 `patches/*.patch` 目标 + `overlay/` 目标做差集。

> ⚠️ **口径教训（必须记住）**：只用 `git diff --name-only` 会把【可执行位丢失】误当成内容改动。
> 经 9P/Windows 拷贝后文件会丢 exec 位（`100755→100644`，`0 增 0 删`）。本文件 11:20 那一版
> 把 2895 项权限位差异错算成“2988 个来自上游的非鸿蒙改动”，**该结论已作废**。

### 7.2 分类结果（权威）
| 分类 | 数量 | 说明 |
|---|---|---|
| 纯权限位变化（`0 增 0 删`） | 2895 | `100755→100644`，9P 拷贝丢 exec 位，**非内容改动** |

| 删除 | 47 | `.sha1` 生成物、web_tests 期望、9P 拷不过来的符号链接、third_party LICENSE 副本 |

- **不存在“未知本地修改”**：真实文本改动 100% 可追溯到本仓 patch 或 overlay。
- 上游 fork `miramira8295/chromium-hmos` 对那 50 个二进制差异覆盖率 = **0**；

实测覆盖率 0（见 §7）后确认它对重建毫无帮助，**已全部删除**；仓库现为「`hmos-154-adapter` 单分支 + `v1.0.0` 单 tag」。

**结论：重建 HAP 不需要上游镜像。** 真外部依赖仍是 §7.3 那五样。

**将来若确实要镜像（例如升级到 155 参考），按这个已验证过的命令做**：

```bash
git clone --mirror https://github.com/miramira8295/chromium-hmos.git /tmp/up.git
git -C /tmp/up.git push <你的仓> \
  'refs/heads/hmos-154-adapter:refs/heads/upstream-hmos-154-adapter' \
  'refs/heads/hmos-155-adapter:refs/heads/upstream-hmos-155-adapter' \
  'refs/heads/build-results:refs/heads/upstream-build-results' \
  'refs/tags/*:refs/tags/upstream/*'
```

- **必须加 `upstream/` / `upstream-` 前缀**：上游有 245 个 `build-*` tag（只指向 42 个 commit），
  直接用原名会和自己 `v1.0.x` 版本 tag 混在一起。
- 两条历史**无共同祖先**：**禁止 merge / cherry-pick / rebase**，只能文件级 diff
  （`git diff upstream-hmos-154-adapter:overlay/<path> hmos-154-adapter:overlay/<path>`）。
- 删除同样简单：`git push <仓> --delete <3个分支>` + 批量 `--delete` 那 245 个 tag。
- 本地临时裸镜像 `D:/hmos-build/_mirror_tmp/chromium-hmos.git`（26MB）留着，随时可推；不用就直接删。
