## 3. WSL src 树 = 运行时状态（不可 git 化，别乱动）

- 全树移植是 **untracked 工作区改动**（大 patch `git apply` 到 base `b510e9d7cd` 上，从未 commit）。
- ⚠️ **绝不 `git clean -fd`**：会删掉整个鸿蒙移植（base/ohos、chrome/browser/ohos、ui/ozone/platform/ohos 等几百个未跟踪文件）。
- 判「引擎真变了」唯一依据 = `sha256sum out/plan_kirin_pc/libweb_engine.so`（`runtime.version` 重编也不变，不能靠它）。
- 全丢重建 SOP：
  1. `bash scripts/apply-adapter.sh`（大 patch + deps/series + 12 个前置补丁 + overlay rsync）
  2. `bash /mnt/d/WorkBuddy/鸿蒙Chrome/wb-wsl-stage3d-patches.sh`（55 个增量补丁 + overlay 同步 + gn gen）
  3. `bash wb-wsl-stage3c-build.sh`（编译）
  4. `bash wb-wsl-stage3e-resources.sh`（pak/locale + 装配）
  5. （可选热修）`打补丁-引擎.cmd` —— Origin 已固化进 patch，正常应全 SKIP
  6. Windows 侧双击 `Vulkan开关-一键构建.cmd` 出 HAP
- 重建后必跑 `verify-originals.sh`，7 个标记全 OK 才说明 5 块原创都在。

## 4. 日常维护规则（写给未来的自己/AI）

**新增一个引擎侧本地修改的标准动作：**
1. 改 `overlay/` 里的文件，或新建 `patches/ohos-<name>.patch`（LF！补丁一律 LF，见 `.gitattributes`）；
2. 注册三处清单：`scripts/apply-adapter.sh`、`scripts/ci-incremental-build.sh`、`wb-wsl-stage3d-patches.sh` 的 PATCHES 列表；
3. `local-patches/MANIFEST.txt` 加行（`git hash-object` 算指纹）+ snapshots 副本 + `verify-originals.sh` 加 marker；
4. `sync-154.cmd` 的 PROTECTED 加上新文件；
5. 本地 commit（不 push）；
6. 若改了管线脚本 → `bash local-pipeline/refresh.sh` → 再 commit。

**血泪反模式（每条都踩过）：**
- ❌ 改 WSL src 不改 overlay → 下次构建被 `rsync overlay/ → src/` 冲掉（桌面 UA 补丁三连败的根因）。
- ❌ 改 `patches/ohos-browser-controls.patch` → 它是副本，不在任何 apply 清单，改了不生效。
- ❌ 让引擎侧修复只活在仓库外 patcher 里 → 本次 Origin 补丁的教训；现在已固化为 git patch。
- ❌ `git clean -fd` → 删掉整个移植。
- ❌ 信「改了就编进去了」→ 唯一硬判据是 .so 的 sha256 变化 + verify-originals 的 7 个标记。
