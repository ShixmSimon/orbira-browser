# 必应首页缩一圈 / 页面底部少一行 —— 修复说明（供 155 线参考）

> 来源：157 线 2026-11-16 真机反馈修复，提交 `1e0929d1` → `15dee9e8` → `8e373898` → `ef1bd2b2`（壳）、`91123053`（引擎）。
> **重要**：这两件事是**两条独立因果，必须拆开修**。早期把它们当成一个问题（"必应特殊，别补偿"）反而修出了第二个 bug。

---

## 一、先厘清机制：补偿为什么会存在

AuraShell 的顶/底条带是**浮在满屏页面之上的 overlay**，不占布局。但引擎侧有两处会真实改变 renderer 视口：

1. **`setBrowserControls(top, minTop, bottom)`**：`minTop < top` 时，顶栏可随滚动收起；此时 renderer 视口底部会恒少一截（引擎按 `minTop` 预留）。
2. **`DoBrowserControlsShrinkRendererSize()`**：决定"顶栏显示时是否收缩 renderer"。**必须恒定返回 false**（见第四节）。

为了抵消 (1) 造成的底部缺口，壳要下发一份 `setViewportInsets(bottom = 补偿值)`。

**补偿的两条铁律**：

- **必须是常量**。按滚动 ratio 连续补（1.0.130 试过）会每帧发 `setViewportInsets` → 频繁 resize renderer → 页面跳动 + 滚动卡顿。已证失败，禁止照搬。
- **同一页内档位不能翻转**。补偿值一旦在某页内变化（例如从 `topSafe` 翻到 `84+topSafe`），引擎就砍掉/放回一截渲染高度，整页做二次布局 → 视觉上"跳一下"。

## 二、Bug A：必应首页整页背景图缩一圈

### 现象
打开 `bing.com` 首页或结果页（`/`、`/search`、`/index.html`），整页背景图比正常小一圈（四周同时往里缩），页面内容跟着缩小。

### 根因
必应首页/结果页整页是一张：

```css
.img_cont { position: fixed; top/right/bottom/left: 0; background-size: cover; }
```

**四边贴齐视口 + cover** 的背景层。这种层对 renderer 视口高度极其敏感：视口高度少 84vp，图就整体缩一圈。

而 **157 的"页内钉住"机制**会让补偿档在页面生命周期内翻转：

```ts
// AuraShell.ets（157）
private isTopBarCollapsing(): boolean {
  return this.hideTopBarOnScroll && !this.topBarPinnedForPage;
}
```

- 用户开了"滚动时隐藏地址栏"，且页面**未钉住** → `collapsing = true` → 补偿 = `topSafe`（约 36vp）
- 必应首页内容不足一屏 → 探针判定"滚不动" → **钉住** → `collapsing = false` → 补偿 = `TOP_BAR_EXTENT_VP + topSafe`（84 + 36vp）

⇒ 补偿档从 36 翻到 120，renderer 视口高度被砍 84vp ⇒ cover 背景图缩一圈。

### 修法（壳，157 的 `AuraShell.ets`）
**补偿永远照发（常量），只在探针里禁止必应封面页钉住**——从源头去掉档位翻转，而不是去减补偿。

**(1) 新增封面页判定**（只认 `bing.com` / `*.bing.com`，路径 `/`、`/search`、`/index.html`）：

```ts
private isBingCoverPage(url: string): boolean {
  const lower = url.toLowerCase();
  const schemeAt = lower.indexOf('://');
  if (schemeAt < 0) return false;
  const afterScheme = lower.substring(schemeAt + 3);
  const slashAt = afterScheme.indexOf('/');
  let host = slashAt < 0 ? afterScheme : afterScheme.substring(0, slashAt);
  const at = host.indexOf('@');   if (at >= 0) host = host.substring(at + 1);
  const portAt = host.indexOf(':'); if (portAt >= 0) host = host.substring(0, portAt);
  if (host !== 'bing.com' && !(host.length > 5 && host.endsWith('.bing.com'))) return false;
  // 取 pathname（去 query / hash），只放行 / 、/search 、/index.html
  // …（完整实现见 157 overlay/chromium-ui/entry/src/main/ets/pages/AuraShell.ets）
}
```

**(2) 探针里对封面页禁止钉住**（`updatePageTopBarPin`）——必须在"钉住"判定**之前**返回：

```ts
const bingCover = this.isBingCoverPage(url);
if (bingCover !== this.probeOnBingCover) {
  this.probeOnBingCover = bingCover;
  this.applyDockViewportInset();      // 判定位翻转时立刻重发内距
}
if (bingCover) {
  if (this.topBarPinnedForPage) {     // 已钉住就先解钉
    this.topBarPinnedUrl = '';
    this.topBarPinnedForPage = false;
  }
  return;                             // 封面页永不走钉住分支
}
```

**(3) 换页时提前定档 + 先解钉再下发内距**（状态快照回调里）。否则第一帧仍用上一页的补偿档，会看到图被拉一下：

```ts
const pageChanged = (state.url ?? '') !== prevUrl ||
                    (state.activeTabIndex ?? -1) !== prevTabIndex;
if (this.topBarPinnedForPage && pageChanged) {
  this.topBarPinnedUrl = '';
  this.topBarPinnedForPage = false;   // 解钉必须在下面的内距下发之前
}
const coverNow = this.isBingCoverPage(state.url ?? '');
if (coverNow !== this.probeOnBingCover) {
  this.probeOnBingCover = coverNow;
  this.applyDockViewportInset();      // 第一次下发就是最终值 ⇒ 全程零二次布局
}
```

## 三、Bug B：页面最底部少一行字（页脚被裁）

### 现象
整页滑到最底，最后一行文字被切掉；有的站点底部固定条（如知乎 `position:fixed` 的「欢迎参与讨论」）被顶栏带走或被裁。

### 根因（两条，都要修）

**B-1 壳侧：补偿档算错 / 被误删**

常显档（`minTop = top`，顶栏不可收）下，renderer 视口底部**恒少** `TOP_BAR_EXTENT_VP + topSafe`，必须用常量补回来：

```ts
// 157 AuraShell.ets —— 正确版本
private topBarPushVp(): number {
  const topSafe = Number(AppStorage.get('auraTopSafeVp') ?? 0);
  if (topSafe <= 0) return 0;
  if (this.homeStyle === 'chrome' && this.dockPosition === 'bottom') {
    return this.hideStatusBarOnScroll ? 0 : topSafe;
  }
  // 常显档必须补 TOP_BAR_EXTENT_VP + topSafe（常量）。
  // 【血的教训】这里曾经写成 if (!this.isTopBarCollapsing() && !this.probeOnBingCover)，
  // 为了治"必应图片缩一圈"把必应排除在补偿之外 —— 结果补偿缺失，页脚最后一行被裁。
  // 必应的缩图必须用"禁止钉住"解决，绝不能靠扣补偿。
  if (!this.isTopBarCollapsing()) {
    return TOP_BAR_EXTENT_VP + topSafe;
  }
  return this.hideStatusBarOnScroll ? 0 : topSafe;
}
```

> 155 线当前用的是 `if (!this.hideTopBarOnScroll)`（设置档判断），**在 155 没有"钉住"机制的前提下这个判断是对的**，`return TOP_BAR_EXTENT_VP + topSafe` 保持一致即可。
> 若 155 也要引入钉住机制，必须同步改成 `!isTopBarCollapsing()`，否则钉住后被判成收起档、补偿变 0 → 页脚又被裁。

**B-2 引擎侧：收缩策略不能随顶栏显隐**

`chrome/browser/ui/browser_web_contents_delegate/browser_web_contents_delegate.cc`：

```cpp
bool BrowserWebContentsDelegate::DoBrowserControlsShrinkRendererSize(
    content::WebContents* contents) {
#if BUILDFLAG(IS_OHOS)
  if (app_browser_controller_) {
    return false;
  }
  // 157 上游版写的是"随顶栏显隐收缩"：
  //     return !AreAuraShellBrowserControlsHidden(contents);
  // 后果：顶栏一收，renderer 立刻长回来 → 页面高度随滚动来回变 →
  // position:fixed 贴视口底的元素跟着上下跳、页面底部被裁。
  // 154/155 的适配层是**恒定 false**：只要顶栏存在就永不收缩。
  // 注意：if 条件必须保留，否则后面 return 变不可达代码，-Wunreachable-code-return 报错。
  if (chrome::ohos::GetAuraShellTopControlsHeight() > 0) {
    return false;
  }
#endif
  return window_->DoBrowserControlsShrinkRendererSize(contents);
}
```

> **155 引擎这处已经是恒定 false（正确），不需要改**。这是 157 移植时被上游写法盖掉的，157 已修（`91123053`）。
> 判断方法：看函数里是 `return false;` 还是 `return !AreAuraShellBrowserControlsHidden(contents);`。

## 四、给 155 线的判定清单

改之前先确认到底复现的是哪一条，别一起改：

| 现象 | 判定 | 修哪里 |
|---|---|---|
| 必应整页背景图四周缩一圈 | 该页是否被钉住 / 补偿档是否在某刻从 `topSafe` 翻到 `84+topSafe` | 壳：探针禁止钉住（Bug A） |
| 页面滑到底最后一行被裁 | `topBarPushVp()` 在常显档是否返回了 `TOP_BAR_EXTENT_VP + topSafe`；是否被某个"特殊站点豁免"扣掉了 | 壳：恢复常量补偿（Bug B-1） |
| 底部 fixed 元素随滚动上下跳 | 引擎 `DoBrowserControlsShrinkRendererSize` 是否随显隐变化 | 引擎：恒定 false（Bug B-2，155 已正确） |

**155 现状（已核对 155 编译树）**：
- `AuraShell.ets` 中 `topBarPinnedForPage` / `topBarPinnedUrl` / `isTopBarCollapsing` **均不存在**（无钉住机制）
- `isBingCoverPage` / `probeOnBingCover` **均不存在**（无必应豁免）
- `topBarPushVp()` 用 `!this.hideTopBarOnScroll`，常显档返回 `TOP_BAR_EXTENT_VP + topSafe`（补偿正确）
- 引擎收缩已是恒定 false（正确）

⇒ **155 若报"必应图片缩一圈"，根因不是钉住机制**（它没有），要另找档位翻转源（例如设置切换时 `hideTopBarOnScroll` 变化 + 内距重发时序）。**155 若报"底部少一行"，先查补偿档是否被扣或算成 0。**

## 五、绝对不要做的事（已踩过的坑）

1. **不要按滚动 ratio 连续补内距**（1.0.130）：每帧 `setViewportInsets` → 频繁 resize → 页面跳 + 滚动卡。补偿必须常量。
2. **不要为了治必应缩图去扣补偿**：那会直接把页脚最后一行裁掉（本次 bug B 的成因）。
3. **不要把引擎收缩改成随显隐变化**：fixed 底元素会跟着上下跳（155 注释里早写明过这个症状）。
4. **不要在页面生命周期内翻转补偿档**：任何"某条件下改补偿值"都要保证同页内恒定，翻转必须发生在换页那一刻、且在下发内距之前完成。
